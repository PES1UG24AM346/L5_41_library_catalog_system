# Static Code Analysis Issues

The following issues were identified across `library_catalog_system.py` using Bandit, Flake8, and Pylint static analysis tools. High and medium severity issues are prioritized first, followed by low severity, refactoring, and style conventions.

| Issue | Type | Line(s) | Description | Fix Approach |
|-------|------|---------|-------------|--------------|
| Command Injection via `os.system` (Bandit B605) | Security (High) | 58 | Starting a process with a shell using `os.system()` with string concatenation (`"echo Catalog backup exported to: " + filename`) introduces a potential shell injection vulnerability if untrusted input is passed. | Remove `os.system()` and use Python's built-in `print()` function directly (e.g., `print(f"Catalog backup exported to: {filename}")`), or use `subprocess.run()` with argument lists and `shell=False`. |
| Weak Cryptographic Hash Function MD5 (Bandit B324) | Security (High) | 47 | Use of `hashlib.md5()` for hashing patron IDs. MD5 is cryptographically weak, broken, and susceptible to collision attacks. | Replace `hashlib.md5()` with a secure cryptographic hashing algorithm such as `hashlib.sha256()`. |
| Arbitrary Code Execution via `eval()` (Bandit B307, Pylint W0123) | Security (Medium) | 42 | Using `eval(calc_expr)` dynamically executes arbitrary Python code from string expressions, which poses a severe security risk if untrusted input is supplied. | Avoid dynamic evaluation entirely by implementing explicit arithmetic calculations or safely evaluating expressions using an AST visitor limited to arithmetic operators. |
| Mutable Default Argument (Pylint W0102) | Bug Risk / Code Quality (Medium) | 15 | `issueBook` defines `active_issues=[]` as a default parameter. Mutable default arguments are evaluated only once at function definition, leading to shared state and unintended side effects across multiple calls. | Replace the default argument with `None` (`active_issues=None`) and initialize a new list inside the function body if `active_issues is None`. |
| Insecure Pseudo-Random Number Generator (Bandit B311) | Security (Low) | 51 | `random.randint()` uses a standard pseudo-random number generator that is deterministic and unsuitable for security-sensitive tokens such as patron PINs. | Replace `random.randint()` with a cryptographically secure random number generator using Python's `secrets` module (`secrets.SystemRandom().randint(1000, 9999)`). |
| Bare `except` with Silent `pass` (Bandit B110, Flake8 E722, Pylint W0702) | Error Handling / Bug Risk (Low) | 26–27 | A bare `except:` block combined with `pass` suppresses all exceptions silently (including `KeyError`, `KeyboardInterrupt`, and `SystemExit`), concealing runtime errors and complicating debugging. | Check key membership explicitly (`if book_id in catalog:`) or catch specific exceptions (`except KeyError:`) and avoid silent exception swallowing. |
| Unmanaged File Resource and Missing Encoding (Pylint R1732, W1514) | Resource Management / Bug Risk (Low) | 55 | Opening a file using `f = open(...)` without a context manager risks file descriptor leaks if exceptions occur before `f.close()`, and omitting encoding can cause platform-dependent encoding issues. | Use a `with open(filename, "w", encoding="utf-8") as f:` context manager to ensure safe resource cleanup and deterministic encoding. |
| Unused Local Variable `late_fee` (Flake8 F841, Pylint W0612) | Code Quality (Low) | 31 | The local variable `late_fee = 1.50` in `check_availability()` is assigned a value but is never referenced or used anywhere in the function. | Remove the unused variable declaration `late_fee = 1.50`. |
| Unused Import `csv` (Flake8 F401, Pylint W0611) | Code Quality / Style (Low) | 6 | The module imports `csv` (`import csv`), but the module is never referenced or used anywhere in `library_catalog_system.py`. | Remove the unused `import csv` statement to keep the namespace clean and improve code readability. |
| Equality Comparison to `None` (Flake8 E711, Pylint C0121) | Code Style / Idiomatic Python (Low) | 32 | Comparison `catalog.get(book_id) == None` uses equality comparison rather than identity comparison `is None`, which violates PEP 8 style conventions. | Replace `== None` with identity check `is None` (e.g., `book is None`). |
| Simplifiable `if-else` Return Statement (Pylint R1703, R1705) | Refactoring / Code Style (Low) | 34–37 | An `if-else` block returning literal `True` or `False` contains redundant branching and an unnecessary `else` block after `return`. | Simplify the expression directly to `return book["copies"] > 0`. |
| Non-PEP8 Function Naming Style `issueBook` (Pylint C0103) | Code Style (Convention) | 15 | The function name `issueBook` uses camelCase instead of the standard Python PEP 8 snake_case naming convention (`issue_book`). | Rename function to `issue_book` and provide `issueBook = issue_book` alias for backward compatibility. |
| Legacy String Formatting (Pylint C0209) | Code Style (Convention) | 19 | Using `%` string interpolation (`"Issued book %s to patron %s" % (...)`) is legacy syntax that is less readable and slower than modern f-strings. | Replace `%` string formatting with Python 3.6+ f-strings (e.g., `f"Issued book {book_id} to patron {patron}"`). |
| Missing Function and Method Docstrings (Pylint C0116) | Documentation (Convention) | Multiple (15, 23, 30, 40, 46, 50, 54, 61) | Functions across the module lack descriptive docstrings explaining their purpose, parameters, and return values. | Add PEP 257 compliant docstrings to all functions and helper utilities. |
| Missing Final Newline (Flake8 W292, Pylint C0304) | Code Style (Convention) | 73 | The file ends abruptly without a trailing newline character, violating POSIX standards and style guidelines. | Add a standard newline character at the end of the file. |
